# 09-01 — KycModule (upsert/list/review) + MANAGER grant + 12-digit fix

> Wave 1. Runs in parallel with 09-02 (zero shared files). Backend-first: module → DTOs → service → controller → mocked-Prisma specs → permissions + validation.

## Objective

Activate the dormant `CustomerKyc` schema (Phase 7 baseline) into a tenant-scoped customer-KYC backend module: staff counter capture (`POST /kyc/customers`), tenant review list (`GET /kyc/customers`), and review decision (`PATCH /kyc/customers/:id/review`) with `kyc.view`/`kyc.verify` permission gates, the MANAGER role grant, and the National ID 12-digit fix. All executable verification is mocked-Prisma (D-14) — no live-DB dependency.

**Purpose:** KYC-01/KYC-02 backend surface the review flow depends on; gates (09-02) read `Customer.kycStatus` produced here.
**Output:** New `backend/src/kyc/` module + dual-column sync + permission catalog consistency + validation fix.

## Requirements

- **KYC-01** — Customer record carries KYC status (`Customer.kycStatus`, denormalized source of truth) linked to `CustomerKyc`; dual-column writes in one interactive `$transaction` (D-01, D-02).
- **KYC-02** — OWNER/MANAGER review surface: `GET /kyc/customers` (`kyc.view`), `PATCH /kyc/customers/:id/review` (`kyc.verify`) (D-04, D-06). Super-admin global customer-KYC review stays deferred (CONTEXT Deferred). Bidder endpoints untouched (D-05).
