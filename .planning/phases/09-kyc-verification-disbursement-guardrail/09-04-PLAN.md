# 09-04 — KYC-05 Storage/RLS Security SQL + Demo Seed

> Wave 2. Depends on 09-01 (09-01 Task 3 already cross-references this plan's SQL for the existing-tenant MANAGER rows). Two standalone deliverables: the Supabase SQL script (run by a human against the live DB — D-14) and an idempotent demo seed script (compile-verified; live run best-effort).

## Objective

Deliver KYC-05: (1) `SECURITY_KYC05_STORAGE_RLS.sql` flipping the `kyc-documents` bucket private, tightening the storage read policy, enabling RLS on `bidder_kyc` with three read tiers, and inserting the MANAGER `kyc.view`/`kyc.verify` mappings for existing tenants; (2) `backend/prisma/seed-demo-kyc.ts` creating VERIFIED demo customers + CustomerKyc rows so the gated demo flow works end-to-end.

**Purpose:** KYC-05 security closure (private bucket + RLS) + demo viability (existing seeds default to NOT_SUBMITTED and would be hard-blocked by 09-02).
**Output:** One root-level SQL script (repo convention) + one tsx seed script.

## Requirements

- **KYC-05** — `kyc-documents` bucket no longer public-read; `bidder_kyc` rows readable only by owning tenant / super-admin (D-12, D-13, D-14).

## Verified Facts (read 2026-08-08)

- **Existing storage setup** (`SUPABASE_STORAGE_RLS_FIX.sql`, repo root): creates `kyc-documents` bucket with `public = true` (`:9`); policy `storage_public_read_supported_buckets` (`:22-28`) grants public SELECT on `('kyc-documents','loan-documents','loan-contracts')`; upload/update/delete policies are `authenticated`-only (`:31-58`).
- **Schema** (`schema.prisma`): `BidderKyc` `:905` — `profileId` unique (`@map("profile_id")`), **no pawnshopId column** (RLS tenant tier must join); `Profile` `:328` — `pawnshopId` optional (`@map("pawnshop_id")`); `Staff` `:241` — verify its pawnshop FK column name (`pawnshop_id` expected, snake_case per convention) while writing the SQL; table names are snake_case (`bidder_kyc`, `profiles`, `staff`).
- **Permission catalog** (`backend/prisma/migrations/20260731120000_v2_schema_baseline/migration.sql`): table `role_permissions(role, permission_id)` with UNIQUE index `role_permissions_role_permission_id_key` on `(role, permission_id)` (`:52-60`); MANAGER rows `:316+` are `('MANAGER','approval.view_queue'),` style. `permissions` table holds the key definitions (`:210+`; `kyc.view`/`kyc.verify` already exist — 09-01).
- **Seed conventions** (`backend/prisma/seed.ts`): `dotenv.config()` + `new PrismaClient()`; cleanup section; customers created with `{ fullName, contactNumber, address }`. `Customer.pawnshopId` is **optional** (`String?`); `CustomerKyc.pawnshopId` is **required** (`String`) — the demo seed must resolve a pawnshopId (env `DEMO_PAWN_SHOP_ID` → fallback `prisma.pawnshop.findFirst()`). `CustomerKyc` requires `customerId`, `pawnshopId`, `status`, `fullName`, `contactNumber`, `address`, `idType`, `idNumber`, `idFrontUrl` (idBackUrl/selfieUrl optional).
- **Scripts**: `prisma:seed` = `tsx prisma/seed.ts`; `tsx` is a devDependency (`^4.7.1`). Run the new script with `npx tsx prisma/seed-demo-kyc.ts` (or `npx tsx` from `backend/`).
- **DB reachability**: dev DB historically unreachable (`getaddrinfo ENOTFOUND`, D-14) — the SQL script and seed script are deliverables; execution against a live DB is a human step. The seed's compile check (`tsc --noEmit`) is the plan's automated gate.

    **Section A — kyc-documents bucket privacy (D-13):**
    - `update storage.buckets set public = false where id = 'kyc-documents';`
    - Drop the old public-read policy: `drop policy if exists "storage_public_read_supported_buckets" on storage.objects;` then recreate it WITHOUT `kyc-documents`: `create policy "storage_public_read_supported_buckets" on storage.objects for select to public using (bucket_id in ('loan-documents', 'loan-contracts'));`
    - **Add the authenticated-scope SELECT policy for kyc-documents (REQUIRED — COVERAGE.md row 13):** `create policy "storage_kyc_documents_authenticated_read" on storage.objects for select to authenticated using (bucket_id = 'kyc-documents');` — Supabase `createSignedUrl` minting with the anon key requires the caller to pass a `storage.objects` SELECT policy on the object; without this `to authenticated` policy, signed-URL creation 403s and every review screen (09-03) breaks after the flip. This is the policy signed-URL callers pass; the `to public` row is dropped so documents are not publicly downloadable regardless of bucket visibility.
    - Leave the authenticated upload/update/delete policies as-is (they are authenticated-only and support the signed-upload flow).

    **Section B — bidder_kyc RLS (D-12), three tiers, all `drop policy if exists` before create:**
    - `alter table bidder_kyc enable row level security;`
    - Own-row read: `create policy "bidder_kyc_own_row_read" on bidder_kyc for select using (auth.uid() = profile_id);`
    - Tenant-staff read (join — bidder_kyc has no pawnshopId): `using (exists (select 1 from profiles p join staff s on s.pawnshop_id = p.pawnshop_id where p.id = bidder_kyc.profile_id and s.id = auth.uid()))` — verify the actual staff pawnshop column name from schema.prisma (`staff` table) before finalizing; adjust the join columns if the mapping differs, but keep the join-through-profile shape (no schema change allowed).
    - Service-role bypass: `create policy "bidder_kyc_service_role_all" on bidder_kyc for all using (auth.role() = 'service_role');`
    - No INSERT/UPDATE/DELETE policies for end users — the bidder and staff write paths go through the NestJS API (service role), so SELECT-only + service-role-all is the intended surface.

    **Section C — MANAGER kyc grants for EXISTING tenants (completes 09-01 Task 3 for live DBs):**
    - `insert into role_permissions (role, permission_id) values ('MANAGER','kyc.view'), ('MANAGER','kyc.verify') on conflict (role, permission_id) do nothing;`
    - Match the exact column names/table from the baseline migration; the unique index makes the conflict target valid.
