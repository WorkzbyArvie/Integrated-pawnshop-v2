# 10-03 — ONB-03: Aggregated onboarding status endpoint (GET /me/status)

> Wave 3 (shares tenant-governance.service.ts + controller with 10-02 — sequential). Backend for ONB-03: one owner-scoped aggregation endpoint that derives the D-10 overall status from the 7 required doc types and surfaces it with rejection reasons. The 10-04 owner dashboard renders this.

## Objective

Add `GET client-registrations/me/status` (D-09) returning the aggregated onboarding state: `{ overall, documents, submissionStatus }` where `overall` follows the D-10 precedence (REJECTED → ACTION_REQUIRED; missing required type → INCOMPLETE; all-verified → APPROVED; else PENDING_REVIEW), aggregated over the owner's most-recent non-CANCELLED registration request, and `documents` carries `rejection_reason` for dashboard copy. Owner-scoped by email — no requestId parameter, no cross-owner reads.

**Purpose:** The single source of truth for the owner dashboard banner (ONB-04) and the REJECTED/ACTION_REQUIRED visibility required by ONB-03.
**Output:** Aggregation service method + controller route + mocked-Prisma specs.

## Requirements

- **ONB-03** — Any document with status REJECTED sets the overall shop onboarding status to REJECTED/ACTION_REQUIRED, exposed via API and reflected in the owner dashboard.

## Verified Facts (read 2026-08-11)

- `listMyClientRegistrationRequests` (:1298-1350) is the owner-request precedent: `getProfileOrThrow` + `lower(owner_email) = lower(${actor.email})` scoping; `ORDER BY created_at DESC LIMIT 500`. It filters `status <> 'DRAFT'` — for the status endpoint we must NOT filter DRAFT (missing-docs draft → INCOMPLETE is the correct signal).
- Owner doc listing precedent: `listRegistrationDocuments` (owner/admin variants) + `adminListRegistrationDocuments` (:1951) use `$queryRaw` with `${requestId}::uuid` binds.
- `REQUIRED_ONBOARDING_DOC_TYPES` — created in 10-01 in `tenant-governance.service.ts` (7 doc types); `PawnshopDocument.document_type` enum values match it (verified: upload allow-list uses the same 7).
- Request statuses (schema): DRAFT, PENDING, CONTACTED, APPROVED, REJECTED, CANCELLED. `submissionStatus` returns the raw request status uppercased.
- Aggregation ordering precedent: App.tsx owner flow (`rows[0]` = most recent) — the status endpoint uses the same most-recent ordering, skipping CANCELLED (a cancelled request should not drive the banner).
- Controller route map (tenant-governance.controller.ts): `@Get('client-registrations/me')` :167, `@Get('client-registrations/:requestId/documents/admin')` :269. NEW `@Get('client-registrations/me/status')` must be placed IMMEDIATELY AFTER the `/me` route (:167) and BEFORE the `:requestId` param routes so Express does not match `me` as `:requestId`. `@Public()` absent → authenticated owner; no `@RequiresPermission` (owner-facing, matches listMyClientRegistrationRequests).
- Spec harness: direct-construction mocks (`profile.findUnique`, `$queryRaw`); ONB-01 gate tests from 10-01 already stub `profile.findUnique` for SUPER_ADMIN/OWNER — extend with an OWNER-with-email fixture.
