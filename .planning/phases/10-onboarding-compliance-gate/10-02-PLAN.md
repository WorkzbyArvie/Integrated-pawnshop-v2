# 10-02 — ONB-02: View-before-approve backend + D-07 permission wiring

> Wave 2 (shares tenant-governance.service.ts with 10-01 — sequential). Backend-first for the review-modal feature: view endpoint persists `hasViewed`, the review endpoint enforces it, and the onboarding permission constants become real `@RequiresPermission` metadata with the SUPER_ADMIN guard allow-list extended in lockstep.

## Objective

Deliver ONB-02 server-side: (D-05) a new SUPER_ADMIN view endpoint that persists `hasViewed=true`/`viewedAt`/`viewedBy` on a registration document; (D-06) `reviewRegistrationDocument` rejects APPROVED unless the document was viewed (REJECTED stays view-free); (D-07) wire the existing `onboarding.review_documents`/`onboarding.approve` constants as `@RequiresPermission` metadata on the admin list/review/view endpoints AND extend `SUPER_ADMIN_PERMISSIONS` so the only permitted reviewer is not 403'd — this is the critical pitfall from 10-RESEARCH (RbacGuard does NOT blanket-bypass SUPER_ADMIN; rbac.guard.ts:119-128).

**Purpose:** Traceability — every approved onboarding document carries `viewed_by`/`viewed_at`; UI disable is never the control (server rejects).
**Output:** View endpoint, hasViewed guard, permission wiring (guard + catalog MATRIX/count), mocked-Prisma specs.

## Requirements

- **ONB-02** — Admin reviews onboarding documents inside the viewer modal; Approve is disabled until the document is opened/viewed (`hasViewed` state persisted server-side).
