# 10-01 — ONB-01: Server-side docs-before-trial gate

> Wave 1. Backend-only. Zero controller/decorator changes → permissions-catalog.spec.ts stays green after this plan. Runs alone (10-02 shares the service file, so it waits).

## Objective

Insert the server-side docs-before-trial gate (ONB-01, D-01..D-04) at the single chokepoint: the APPROVED branch of `reviewClientRegistrationRequest` (tenant-governance.service.ts:1459), immediately before `ensureTenantModuleConfigTable()` (:1460). When the SUPER_ADMIN approves a registration, the service first verifies every one of the 7 required document types (D-02) exists for the request with status ∈ UPLOADED/UNDER_REVIEW/VERIFIED (D-03); otherwise APPROVED is rejected with a clear 400 listing the missing types and no trial/pawnshop side effects occur. Trial activation behavior is otherwise unchanged (D-04). No schema or migration work — `PawnshopDocument` already carries everything.

**Purpose:** Close the audit finding "Docs-before-trial gate MISSING" — the gate is enforced server-side on the approval path, not just in the UI.
**Output:** Gate block + shared 7-type constant in `tenant-governance.service.ts`; mocked-Prisma spec coverage for gate pass/fail/skip.

## Requirements

- **ONB-01** — Owner cannot initialize Free Trial until all required regulatory documents are submitted and at least pending review — enforced server-side (approval path).

## Verified Facts (read 2026-08-11)

- `reviewClientRegistrationRequest` APPROVED branch begins at :1459 (`if (decision === 'APPROVED')`) and calls `ensureTenantModuleConfigTable()` at :1460 — the gate inserts between the `if` and this call. The finalized-request guard (`:1447-1454`: `['APPROVED','REJECTED','CANCELLED'].includes(request.status) && decision !== request.status` → 400) runs before the gate and stays untouched.
- After the gate: `pawnshop.findFirst` (:1462) → existing-or-create → `adminInvite.findFirst/create` (:1534-1555) → profiles `$executeRaw` (:1557) → `subscription.findFirst` ×3 + optional `subscription.create` (:1574-1625) → docs `pawnshop_id` backfill `$executeRaw` (:1627-1634). All of this must NOT run when the gate fails.
- REJECTED/CONTACTED decisions share the tail (:1637-1675: status `$executeRaw` + SYSTEM message INSERT) and never touch the doc gate.
- Upload allow-list (`uploadRegistrationDocument` :1874-1877) = the exact D-02 7 types. `ComplianceDocStatus` enum (schema.prisma:1684) = UPLOADED/UNDER_REVIEW/VERIFIED/REJECTED/EXPIRED.
- `pawnshop_documents.registration_request_id` is indexed (schema.prisma:1718). Existing module style binds enum literals with `::"ComplianceDocType"` / `::"ComplianceDocStatus"` casts (:1885, :1897).
- `Prisma` namespace already imported in the service (`Prisma.InputJsonValue` at :1474, `SubscriptionStatus` at :1578) — `Prisma.sql` / `Prisma.join` are available for safe dynamic enum-array binding (no string interpolation of the type list; each value becomes a bound parameter).
- Existing spec harness: `tenant-governance.service.spec.ts` constructs `new TenantGovernanceService(prisma as any)` with `prisma = { profile: { findUnique }, pawnshop: { findUnique }, $queryRaw, $executeRaw }` and `jest.spyOn(service as any, 'logAudit')`. The `kyc.service.spec.ts` `Test.createTestingModule` harness (typed mock + `jest.fn`) is the modern pattern to extend here.

    - One `$queryRaw` that returns the required types with NO acceptable doc (per D-03, acceptable status ∈ UPLOADED, UNDER_REVIEW, VERIFIED):
      ```ts
      const requiredTypeSql = REQUIRED_ONBOARDING_DOC_TYPES.map(
        (t) => Prisma.sql`${t}::"ComplianceDocType"`,
      );
      const missing = await this.prisma.$queryRaw<Array<{ doc_type: string }>>`
        SELECT t.doc_type
        FROM (SELECT UNNEST(ARRAY[${Prisma.join(requiredTypeSql, ', ')}]) AS doc_type) t
        LEFT JOIN public.pawnshop_documents d
          ON d.registration_request_id = ${requestId}::uuid
         AND d.document_type = t.doc_type
         AND d.status IN ('UPLOADED', 'UNDER_REVIEW', 'VERIFIED')
        WHERE d.id IS NULL
      `;
      ```
      (Prisma.join binds each enum value as a parameter — no user input is ever interpolated into SQL text; the literal `'UPLOADED','UNDER_REVIEW','VERIFIED'` IN-list follows the existing literal-enum-cast style of the module.)
    - If `missing.length > 0`: `throw new BadRequestException('Cannot approve: missing or incomplete required documents: ' + missing.map((m) => m.doc_type).join(', '))`. The 400 aborts before `ensureTenantModuleConfigTable()` runs, so no pawnshop/tenant-config/subscription writes occur.
    - Non-APPROVED decisions (CONTACTED/REJECTED) continue to skip the gate (the block is inside `if (decision === 'APPROVED')`).
