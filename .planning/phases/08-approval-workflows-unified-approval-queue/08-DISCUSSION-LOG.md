## Appraisal Hold State

| Option | Description | Selected |
|--------|-------------|----------|
| Hold in PENDING_APPROVAL | appraiseTicket transitions RECEIVED → PENDING_APPROVAL (already in state machine). OWNER/ADMIN approve → OFFER_MADE; reject → back to RECEIVED for re-appraisal. Appraisal data stored in ApprovalRecord payload, applied to ticket only on approval. | ✓ |
| Gate at APPRAISED → OFFER_MADE | Keep appraise → APPRAISED as-is, add a new gate so APPRAISED → OFFER_MADE requires approval. More states, extra transition wiring. | |

**Notes:** Reuse existing state machine transitions (pawn-lifecycle.ts:8-10). Do not write loanAmount to ticket at appraisal-submission time.

## Redemption Threshold Config

| Option | Description | Selected |
|--------|-------------|----------|
| Pawnshop.settings, default ₱50k | Per-tenant key in Pawnshop.settings JSON (e.g. redemptionApprovalThreshold, default ₱50,000), editable via existing PATCH /pawnshops/:id/settings. Follows finance/payroll precedent. | ✓ |
| Env var | A global threshold env var (e.g. REDEMPTION_APPROVAL_THRESHOLD). Simpler but same for all tenants. | |
| Both (settings override env) | settings value overrides an env default fallback. Most flexible, slightly more code. | |

**User's choice:** Pawnshop.settings, default ₱50k
**Notes:** amountPaid (redeem-ticket.dto.ts:5) is the value compared against the threshold.

## Approval Side Effects & Resubmission

| Option | Description | Selected |
|--------|-------------|----------|
| Approve→OFFER_MADE, reject→RECEIVED | Appraisal approve → OFFER_MADE (contract still generated by existing approve action; appraisal values + proof emitted on approval). Reject → RECEIVED with comment so appraiser edits & resubmits. | ✓ |
| Approve→OFFER_MADE + auto contract | Appraisal approve → OFFER_MADE AND auto-generate loan contract in the same call, so ticket is fully ready for signing. Fewer clicks but couples approval to contract generation. | |

**User's choice:** Approve→OFFER_MADE, reject→RECEIVED
**Notes:** Redemption approve runs existing redeemTicket release logic; reject keeps ticket ACTIVE/GRACE_PERIOD with notification. Every decision persists to ApprovalRecord with approver identity and comment.
