# Phase 10.1 Plan 09: Dashboard tracer UI — forced gate and first Account Security slice Summary

Owner guidance, server-status preflight, fail-closed forced change, backend-authoritative recovery,
and universal own-account password/activity access — the first end-to-end browser journey of the phase.

## What Was Built

**Task 1 — Shared password presentation and backend-authoritative recovery** (`50ee8c3`)

- `PasswordRequirements.tsx` now owns every binding string (`heading`, `mismatch`, `show`, `hide`) so
  the checklist, visibility labels, and mismatch copy have one source of truth.
- `PasswordField.tsx` gained `PasswordConfirmField` — a single-sourced confirmation field that
  always uses `autoComplete="new-password"` and never re-renders the checklist.
- `ResetPassword.tsx` was rewritten from a 4-state component into the full UI-SPEC recovery state
  machine: request-email (ready/sending/sent/invalid-email/failed/rate-limited with 60s cooldown) and
  reset-link (validating/ready/invalid/expired/incomplete/validation-failed) surfaces plus the
  password-update (submitting/rejected/not-cleared/success) path.
- Recovery authority moved to the server. `supabase.auth.updateUser` is transport-only; success is
  shown only after `POST /security/recovery/complete` resolves **and** a
  `GET /security/credential-status` refetch reports `mustChangePassword=false`. If the refetch still
  reports the forced change, the gate shows `Your password change has not cleared yet. Try again.`
- The auto-advance `setTimeout` redirect was removed; `Continue to sign in` is now an explicit action.
- `LandingPage.tsx` confirm field switched to `PasswordConfirmField` (was a hand-duplicated
  `PasswordField` with copied props).

**Task 2 — Fail-closed preflight, blocking gate, Account Security** (`ba39fc4`)

- `ForcedPasswordChangeGate.tsx` renders the approved blocking surface in the documented visual
  order: lock icon → `Action required: password change` badge → `Update your password to continue`
  heading (focused on mount) → legacy explanation → own-account/tenant context → current/new/confirm
  fields with checklist → `Update password and continue` → `Use password recovery` + `Sign out`.
  It has no close control, no Escape handler, no outside-click path, and no route to operational
  content. Gate clearance is server-driven: the change mutation must succeed **and**
  `onStatusChanged()` must return a status with `mustChangePassword=false`.
- `CredentialStatusLoading` / `CredentialStatusUnavailable` render the fail-closed status surfaces
  with `Try again`, `Use password recovery`, and `Sign out`.
- `AccountSecurityPage.tsx` implements the asymmetric 60/40 layout: header with own-account context
  and compact status row, password section (status, last-changed, `Change password` inline editor),
  email MFA status section, and full-width recent activity. MFA enrollment/disable controls are
  deliberately deferred to 10.1-13.
- `App.tsx` now loads `GET /security/credential-status` after session restoration and evaluates it
  **before** pending-owner, subscription-frozen, tenant, and operational rendering. Legal and
  recovery routes are excluded so their routing is preserved. `/account-security` was added to
  `TAB_TO_PATH` (so `PATH_TO_TAB` derives it) with a universal `ACCOUNT_SECURITY_NAV_ITEM` kept
  outside `STATIC_NAV_ITEMS`, and guards were added to the impersonation and frozen-tab effects so
  they cannot redirect the universal route away.

## Deviations from Plan

### Added Files

**1. `frontend/src/lib/accountSecurity.ts` (new shared credential client)**
- **Reason:** Four call sites (App preflight, the gate, Account Security, recovery) need the same
  status projection, safe-error mapping, activity normalisation, email masking, and the fail-closed
  access decision. The plan scoped `apiClient.ts` to safe-envelope handling only and left no home for
  this. A single module avoids triplicating the 10.1-08 route contract.
- **Impact:** Pure addition; `apiClient.ts` was left unmodified.

**2. `frontend/src/components/__tests__/ResetPassword.test.tsx` (new test file)**
- **Reason:** D-10 (recovery success only after backend completion plus a status refetch) is a
  Task 1 acceptance criterion, but the plan's Task 1 verify command named only
  `PasswordField.test.tsx`, which cannot observe the recovery flow. Without this file the criterion
  would have been unverifiable.
- **Impact:** Additional focused test file; the plan's verify command still passes unchanged.

**3. `.planning/phases/10.1-.../deferred-items.md`**
- **Reason:** Required by the scope-boundary rule to record out-of-scope discoveries.

### Auto-fixed Issues

**4. [Rule 1 - Bug] Focus return landed on an unmounted trigger**
- **Found during:** Task 2, RED/GREEN
- **Issue:** `AccountSecurityPage` called `changeTriggerRef.current?.focus()` in the same tick as
  `setEditing(false)`; the ref was still null because the editor had not yet unmounted, so success
  never returned focus to the `Change password` trigger.
- **Fix:** Moved focus into an effect keyed on `editing`/`changed`.
- **Files:** `frontend/src/pages/AccountSecurityPage.tsx`
- **Commit:** `ba39fc4`

### Additive Scope

**5. Pending-owner route access.** The pending-owner early return previously bypassed the entire
shell, which would have made `/account-security` unreachable for a pending owner and violated the
UI-SPEC navigation matrix row "Pending owner | Always available in Access/mobile path". The early
return now renders `AccountSecurityPage` when `activeTab === 'account-security'`. The pending
dashboard itself is unchanged.

**6. Mobile access path.** The active desktop sidebar is `hidden lg:flex` and the app has no mobile
menu. A compact `lg:hidden` bar inside `<main>` now carries the `Account Security` entry with a
44px hit area and `aria-current="page"`, per UI-SPEC "Mobile access". Per PATTERNS line 427 the dead
`frontend/src/components/Sidebar.tsx` was deliberately not revived or rewritten.

**7. Sidebar `aria-current="page"`** added to the shared nav button so the active state is not
communicated by the gold dot alone.
