<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flutter form/BLoC → backend security API | Passwords and codes are untrusted and only the backend can verify or write credentials. |
| BLoC/repository → SecureStorage | Only Supabase session data may persist; credential secrets must not. |
| CredentialGate → KycGate/Home | Stale local state and back gestures must not reveal operations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10.1-161 | Information Disclosure | Password, OTP, or assertion in SecureStorage or Semantics | critical | mitigate | Transient state, negative storage tests, and safe widget semantics. |
| T-10.1-162 | Spoofing | Mobile assertion replay across sessions | high | mitigate | Server session binding and in-memory holder cleared at logout and new login. |
| T-10.1-163 | Elevation of Privilege | Home or KYC mounted behind unknown, forced, or MFA state | critical | mitigate | CredentialGate ordering, back handling, and no-child-mount tests. |
| T-10.1-164 | Tampering | Local MFA state mutation | high | mitigate | UI updates only after server response and cancellation tests. |
| T-10.1-165 | Information Disclosure | Cross-user mobile activity or status | high | mitigate | Own-profile backend projection and no target profile parameter. |
| T-10.1-SC | Tampering | npm/pip/cargo installs | low | accept | No new Flutter package; existing BLoC, Dio, Supabase, and mocktail facilities are reused. |
</threat_model>
