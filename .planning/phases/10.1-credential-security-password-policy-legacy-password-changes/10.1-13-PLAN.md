<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OTP input/dialog → backend | Code and current password are untrusted request values. |
| Account Security → API status | Client cannot mark MFA enabled or disabled without a server response. |
| apiClient memory → protected header | Assertion is bearer-like and must be current-session scoped. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10.1-131 | Information Disclosure | OTP or assertion rendered or persisted | critical | mitigate | Memory-only state, safe projections, and no-secret tests. |
| T-10.1-132 | Tampering | Client-only MFA status toggle | high | mitigate | Explicit request sequence and refetch after server success. |
| T-10.1-133 | Spoofing | Cross-session assertion reuse | high | mitigate | Clear on session boundaries and attach only the current memory value. |
| T-10.1-134 | Denial of Service | Unbounded code or resend attempts | high | mitigate | Server throttles and lockout plus 60-second UI cooldown. |
| T-10.1-SC | Tampering | npm/pip/cargo installs | low | accept | No new package; existing Radix, Lucide, and Vitest facilities are reused. |
</threat_model>
