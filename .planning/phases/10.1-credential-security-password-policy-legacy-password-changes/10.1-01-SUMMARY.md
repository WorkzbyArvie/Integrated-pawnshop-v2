## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking integration] Preserved structured policy errors through the global exception boundary**
- **Found during:** Task 1 HTTP tracer verification
- **Issue:** The existing global filter discarded `HttpException` machine codes and `data.failed`, so the owner API could not return the required structured policy failure in the real NestJS surface.
- **Fix:** Extended `GlobalExceptionFilter` to retain safe string error codes and failed rule keys without forwarding arbitrary response data.
- **Files modified:** `backend/src/common/filters/global-exception.filter.ts`
- **Verification:** `backend/test/credential-security.e2e-spec.ts` passed and asserted `PASSWORD_POLICY_FAILED` plus `minLength` without a password echo.
- **Committed in:** `88eefb1`

**2. [Rule 3 - Blocking DI] Wired shared security providers into the Nest module graph**
- **Found during:** Task 1 implementation
- **Issue:** `AppService` and `SecurityService` could not consume the new policy/state services or the shared Supabase admin client through the existing module graph.
- **Fix:** Registered and exported `PasswordPolicyService` and `CredentialStateService`, injected the shared Supabase service, and updated the directly affected service test providers.
- **Files modified:** `backend/src/security/security.module.ts`, `backend/src/security/security.service.ts`, `backend/src/app.service.ts`, `backend/src/app.service.spec.ts`
- **Verification:** Focused Jest suites and backend TypeScript typecheck passed.
- **Committed in:** `88eefb1`

**3. [Rule 2 - Security] Removed secret-bearing local session-token persistence**
- **Found during:** Task 1 owner landing-page integration
- **Issue:** The existing owner flow copied Supabase access and refresh tokens into `localStorage` even though the browser Supabase client already owns the session.
- **Fix:** Removed the redundant token writes and retained only Supabase session state; password and verification-code values remain in component memory and are cleared after success or sign-out.
- **Files modified:** `frontend/src/pages/LandingPage.tsx`
- **Verification:** Frontend component storage regression and TypeScript typecheck passed.
- **Committed in:** `88eefb1`

**4. [Rule 3 - Plan integration] Added the tracer status route in `AppController`**
- **Found during:** Task 1 HTTP acceptance test
- **Issue:** The plan requires a subsequent credential-status request in the owner tracer, while the canonical `/security/credential-status` projection is assigned to 10.1-08.
- **Fix:** Added authenticated `GET /auth/credential-status` backed by the profile-scoped state service for this tracer only; the later security plan can add the canonical security projection without changing the state contract.
- **Files modified:** `backend/src/app.controller.ts`, `backend/src/app.service.ts`
- **Verification:** Deterministic HTTP e2e passed for registration, state initialization, status retrieval, and native login.
- **Committed in:** `88eefb1`
