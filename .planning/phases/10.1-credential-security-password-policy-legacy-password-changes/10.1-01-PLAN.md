<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public owner signup form → NestJS auth routes | Untrusted email, password, role, and verification-token input crosses the public API. |
| Authenticated browser → SecurityController/AccountSecurityGuard | A bearer token and client-supplied body must not be trusted to choose another profile or bypass forced state. |
| NestJS → Supabase Auth/Prisma | Supabase owns password verification/write; Prisma owns profile-scoped state/audit data. |
| Browser storage → security UI | A compromised page must not find a password, raw code, or service credential in persistent browser storage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10.1-11 | Tampering | Public registration bodies bypass class-validator | high | mitigate | Use a decorated account-registration DTO and retain the global whitelist/forbid-unknown pipe; source-scan the controller boundary. |
| T-10.1-12 | Spoofing | Stale local password hash accepts a changed credential | critical | mitigate | Supabase-only `loginNative` in 10.1-01, ordered field/data retirement in 10.1-17, and a tracked-source regression test. |
| T-10.1-13 | Elevation of Privilege | Forced account calls an operational API directly | critical | mitigate | Register `AccountSecurityGuard` after RbacGuard, allow only recovery/status paths, and test the raw 403 path. |
| T-10.1-14 | Information Disclosure | Status/activity returns another tenant or exposes secrets | high | mitigate | Derive profile id from the bearer, scope all reads by authenticated profile, return only safe projections, and audit without secret metadata. |
| T-10.1-15 | Tampering | Password changes without current-password proof | high | mitigate | Require currentPassword, verify through Supabase, assert the shared policy, update server-side, clear state only after success. |
| T-10.1-16 | Repudiation | Failed password/forced-change attempt has no durable trace | high | mitigate | Write a failure-first security log and update its outcome after the Supabase mutation; preserve actor/target/tenant/timestamp. |
| T-10.1-SC | Tampering | npm/pip/cargo installs | low | accept | No new package is needed; the plan reuses installed Nest, Prisma, Supabase, class-validator, React, and Vitest facilities, so there is no phase install task to audit. |
</threat_model>
