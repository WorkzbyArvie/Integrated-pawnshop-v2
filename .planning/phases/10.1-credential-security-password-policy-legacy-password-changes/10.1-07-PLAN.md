# 10.1-07 — Flutter bidder credential parity and native navigation

> Separate parity plan because Flutter uses a clean-architecture/BLoC chain, SecureStorage, Dio, Semantics, and a monolithic main shell. It consumes the same Plan 03/04 backend contracts as the web clients and does not add TOTP, SMS, or any unrelated mobile feature.

## <objective>
Bring the Flutter bidder account surface to the same credential-security contract without creating a client-side authority.

Purpose: SEC-01 through SEC-06 apply to mobile bidders, and the UI-SPEC explicitly requires native focus/semantics, safe-area behavior, forced/MFA gates, Account Security navigation, and no secret persistence.

Output: Shared mobile password policy, credential status model/data/repository/use-case/BLoC chain, in-memory assertion header lifecycle, native credential gate, Account Security/recovery/signup/login surfaces, navigation wiring, and Flutter tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flutter form → backend security API | Passwords/codes and session state cross an untrusted mobile input boundary. |
| BLoC/repository → SecureStorage | Only Supabase session tokens/user id may persist; credential secrets must not. |
| BackendApiService → protected backend routes | The in-memory assertion is bearer-like and session-scoped. |
| CredentialGate → KYC/Home navigation | A stale widget/back gesture must not bypass server-owned status. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10.1-61 | Information Disclosure | Password/OTP/assertion written to SecureStorage or Semantics | critical | mitigate | Restrict storage methods, memory-only transient state, clear controllers/assertion, and negative widget/repository tests. |
| T-10.1-62 | Spoofing | Mobile assertion replay across sessions | high | mitigate | Backend session binding plus in-memory holder cleared on logout/new login; mobile tests cover lifecycle. |
| T-10.1-63 | Elevation of Privilege | Stale/local profile state bypasses forced/MFA gate | critical | mitigate | CredentialGate fetches status before KycGate/Home, handles back safely, and tests no operational child mount. |
| T-10.1-64 | Tampering | Local MFA status changed without server confirmation | high | mitigate | UI updates state only after backend response and preserves enabled state on cancellation/failure. |
| T-10.1-65 | Denial of Service | Mobile code guessing/resend flood | high | mitigate | Backend throttles/lockout from Plan 03 plus native cooldown/no auto-submit and clear error focus. |
| T-10.1-66 | Information Disclosure | Cross-user mobile activity/status | high | mitigate | Own-profile backend projection and no target profile parameter in mobile API calls. |
| T-10.1-SC | Tampering | npm/pip/cargo installs | low | accept | No new Flutter package is needed; existing BLoC, Dio, Supabase, secure storage, mocktail, and bloc_test dependencies are reused, so there is no phase install task to audit. |
</threat_model>
