<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BLoC/use case → backend security API | Credential state and requests cross the untrusted mobile input boundary. |
| Repository → SecureStorage | Only Supabase session tokens/user id may persist. |
| BackendApiService → protected routes | The in-memory assertion is bearer-like and session-scoped. |
| Status response → BLoC | Missing/unavailable state must not become a normal authenticated state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10.1-61 | Information Disclosure | Password/OTP/assertion written to SecureStorage | critical | mitigate | Restrict storage methods, transient in-memory state, and negative repository tests. |
| T-10.1-62 | Spoofing | Mobile assertion replay across sessions | high | mitigate | Backend session binding plus in-memory holder cleared on logout/new login. |
| T-10.1-63 | Elevation of Privilege | Missing/unavailable state becomes normal BLoC state | critical | mitigate | Explicit unavailable/forced/MFA states and bloc tests. |
| T-10.1-64 | Tampering | Client changes MFA state without server response | high | mitigate | Repository/service orchestration and state transitions only after confirmed response. |
| T-10.1-65 | Information Disclosure | Cross-user mobile activity/status | high | mitigate | Own-profile API projection with no target profile parameter. |
| T-10.1-SC | Tampering | npm/pip/cargo installs | low | accept | No new Flutter package; existing BLoC/Dio/Supabase/mocktail stack is reused. |
</threat_model>
