# 10.1-04 — Administrative credential reset, permission catalog, and audit completion

> This backend hardening plan closes the remaining SEC-01/SEC-06 surfaces after the tracer and MFA backend. It deliberately reuses `user.manage_staff`; adding a new permission would churn the catalog without improving authorization.

## <objective>
Harden administrative credential actions and make the permission/audit regressions explicit.

Purpose: The current inline staff-reset body bypasses DTO validation, the current service has no forced state, and the current role mapping does not represent the service's existing Admin/Super Admin behavior. A permission decorator without matching catalog/guard/seed updates would either lock out legitimate operators or silently create a new authorization gap.

Output: Validated/tenant-safe staff reset, preserved role behavior, synchronized permission counts/matrix, and source/audit regression coverage.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Owner/Admin/Manager → staff reset API | A privileged browser supplies a target id and temporary password that must be tenant- and permission-checked. |
| RbacGuard → credential service | The permission decorator and service checks must agree for Admin, Manager, Owner, and Super Admin. |
| SecurityService → SecurityLog/tenant audit | Cross-system writes must be attributable without copying secrets. |
| Runtime auth source → policy service | A second verifier or regex would recreate the split-brain credential defect. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10.1-31 | Elevation of Privilege | Staff reset route without permission metadata or wrong role tuple | critical | mitigate | Reuse `user.manage_staff`, add decorator/throttle, update MATRIX/known tuple, preserve Admin/Super Admin mappings, and run the catalog spec. |
| T-10.1-32 | Tampering | Cross-tenant target id in staff reset | high | mitigate | Resolve actor/target profiles server-side, require same pawnshop for non-Super-Admin, and test both allowed and denied cases. |
